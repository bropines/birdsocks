<h1 align="center">BirdSocks</h1>

<p align="center">
  <strong>Неофициальный клиент NetBird для Android: ваша сеть NetBird для приложений через SOCKS5-прокси</strong>
</p>

<p align="center">
  <a href="readme.md">English</a> | <strong>Русский</strong>
</p>

BirdSocks запускает на телефоне настоящий клиент [NetBird](https://netbird.io)
как узел в пространстве пользователя. Приложения попадают в сеть через
локальный SOCKS5-прокси и DNS-прокси. VPN-слот Android при этом не нужен,
поэтому BirdSocks уживается с другим VPN, блокировщиком рекламы или
прокси-клиентом вроде Throne. Для приложений, которые не умеют работать
через прокси, есть VPN-режим.

Основа проекта взята из [TailSocks](https://github.com/bropines/tailsocks).

> 0.1.0 ещё не выпущена. Что сделано — в [`CHANGELOG.md`](CHANGELOG.md),
> что дальше — в [дорожной карте](docs/ROADMAP_RU.md).

## Возможности

- **Вход:** NetBird Cloud или свой сервер, через браузер (SSO) или по ключу установки.
- **Несколько аккаунтов:** у каждого свои ключи и настройки, переключение с главного экрана.
- **SOCKS5-прокси, по умолчанию `127.0.0.1:48125`:**
  - достаёт до узлов, их сетей и DNS-имён NetBird;
  - остальное отправляет прямо в интернет или через выходной узел;
  - поддерживает UDP;
  - может требовать логин и пароль, может быть открыт в локальную сеть.
- **DNS-прокси, `127.0.0.1:48153`:**
  - сначала отвечает именами NetBird;
  - остальные имена отправляет резолверам сети или вашим;
  - имя из сети NetBird никогда не уходит в публичный DNS.
- **VPN-режим (TUN):** для приложений без настроек прокси. По умолчанию через него идут только диапазоны NetBird; весь трафик — если вы попросите или включён выходной узел. Приложения можно исключать.
- **Узлы и сети:** путь до узла (P2P или relay), задержка, трафик. Выбор сетей и выходного узла; выходной узел, через который интернет не работает, помечается.
- **Экран DNS:** проверка прокси, поиск имён, DNS-серверы сети и записи, которые сервер выдал этому устройству.
- **Подключение к серверу:** если сеть блокирует сервер NetBird, можно подключаться к нему через SOCKS5- или HTTP-прокси либо через встроенный ByeDPI.
- **Доступ и публикация:**
  - узлы могут заходить на сервисы самого телефона: adb, sshd из Termux, веб-сервер;
  - локальный порт можно опубликовать наружу через обратный прокси NetBird.
- **Диагностика:**
  - состояние подключения и серверов;
  - события NetBird, предупреждения приходят уведомлениями;
  - проверка доступа (что файрвол делает с пакетом);
  - захват пакетов в `.pcap`, логи, отладочный архив.
- **Вокруг приложения:** плитка быстрых настроек, запуск при загрузке, ссылки `birdsocks://` на любой экран.

## Как это устроено

```
приложения ──SOCKS5──► прокси BirdSocks ─┬─► netstack NetBird ──WireGuard──► узлы
приложения ──DNS─────► DNS BirdSocks ────┤                                   (P2P или relay)
VPN-режим: VPN Android → hev-socks5-tunnel → тот же прокси
                                         └─► интернет, напрямую или через выходной узел
```

Демон NetBird (`client/server` из закреплённого релиза и несколько патчей
поверх) работает отдельным процессом в режиме netstack. Приложение общается с
ним через его gRPC API. Подробности — в [`agents.md`](agents.md).

## Как начать

1. Установите APK, откройте BirdSocks и войдите: выберите NetBird Cloud или свой сервер, дальше браузер или ключ установки.
2. Укажите приложениям прокси `127.0.0.1:48125` — SOCKS5 с удалённым DNS (`socks5h`). Если у приложения нет настроек прокси, его трафик может довезти до BirdSocks прокси-клиент вроде Throne или AdGuard.
3. DNS: `127.0.0.1:48153` — там, где его можно указать. Иначе включите VPN-режим в «Настройки → Режим туннеля».

Связки с AdGuard и Throne, подключение к серверу через прокси или ByeDPI и
что делать, если не подключается, — в [руководстве](docs/GUIDE_RU.md).
