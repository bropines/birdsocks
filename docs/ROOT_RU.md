# Режим Root

Режим Root — это режим VPN без VPN-слота Android. С root (Magisk, KernelSU,
APatch) BirdSocks создаёт настоящий сетевой интерфейс на NetBird-адресе
устройства и направляет в него трафик правилами маршрутизации Linux, так что
слот остаётся другому VPN или блокировщику рекламы.

Включается в **Настройки → Режим туннеля → Root**. Root-менеджер спросит один раз.

## Как это устроено

Демон NetBird, как и в любом режиме, работает от имени приложения. Маленький
помощник — тот же бинарник демона, запущенный как `libnetbird.so -root-tun`
через `su`, — создаёт интерфейс (`birdsocks0`, у отладочной сборки
`birdsocksd0`), передаёт его демону через unix-сокет и ставит маршрутизацию.
Помощник живёт ровно столько, сколько открыт канал к нему от приложения: при
остановке BirdSocks, гибели приложения, когда демон отпускает интерфейс, или по
сигналу он убирает все свои правила. Если помощника убили принудительно,
правила остаются; следующий помощник убирает их перед стартом.

## Что он занимает: три уровня

`ip rule` проверяется по возрастанию приоритета, и любое правило ниже правил
netd (10000 и выше) срабатывает раньше правил приложений другого VPN. Поэтому
маршрутизация разбита на уровни — по тому, сколько устройства занимает каждый:

| Уровень | Правила | Что занимает |
|---|---|---|
| **T1 — NetBird** | приоритет 90: `to <диапазон NetBird> iif lo lookup 25203` и то же для резолвера `198.18.0.2` | только пакеты устройства к адресам NetBird |
| **T2 — весь трафик** | приоритет 201: `fwmark 0x0/0x20000 iif lo lookup 25204`; локальная сеть возвращается Android на 151, исключённые приложения на 191 | всё, пока выбран выходной узел, сеть или «Весь трафик» |
| **T3 — DNS** | nat-цепочка `BIRDSOCKS_DNS`: порт 53 на `198.18.0.2` | все DNS-запросы устройства |

Пакеты самого приложения обходят всё это на приоритете 89: соединения демона с
WireGuard, relay и signal должны идти в реальную сеть.

- **Защита CGNAT.** Диапазон NetBird по умолчанию, 100.64.0.0/10, — это и
  операторский NAT. Префикс внутри него на чужом интерфейсе — адрес мобильного
  оператора, другой туннель — получает `throw`-маршрут в таблице 25203, и его
  трафик остаётся в своей сети.
- **Локальная сеть.** С включённым «Оставить локальную сеть» (по умолчанию)
  сети, в которых находится телефон, возвращаются Android, когда туннель берёт
  весь трафик, даже если пир маршрутизирует ту же подсеть. **Исключённые
  диапазоны** — `throw`-маршруты в таблице 25204, так что более точный маршрут
  NetBird всё равно выигрывает.
- **Исключённые приложения** обходят T2, но адреса NetBird (T1) им доступны.
  Для DNS исключение действует только на приложения, которые разрешают имена
  сами (браузеры со своим резолвером, Termux, DoH-приложения): за обычное
  приложение запросы отправляет резолвер Android под своим uid.
- **rp_filter** ослабляется, пока стоит T2 (ответы демону не прошли бы через
  него строгую проверку обратного пути), и восстанавливается после; старое
  значение до этого хранится в `/data/adb/birdsocks/rp_filter.orig`.
- **DNS ждёт и уступает.** Перенаправление ждёт, пока Android проверит сеть
  (его проверка идёт через системный резолвер), и снимается после трёх
  неудачных проверок резолвера NetBird — до тех пор, пока он не ответит снова.

## Рядом с другим VPN

T1 уживается с чем угодно: нормальный VPN не маршрутизирует диапазон NetBird к
себе. У T2 и T3 один владелец на устройство. Каждые пять секунд помощник ищет
другой VPN — интерфейс `tun`/`ppp`/`wg`/`ipsec`, на который указывают
поприложенческие правила Android, — и:

| Другой VPN | BirdSocks ставит | Главная карточка |
|---|---|---|
| нет | T1 + T2 + T3 | Root |
| забирает все приложения | только T1: адреса NetBird работают из всех приложений; без выходного узла, сетей и DNS для всего устройства | Root · только NetBird |
| пропускает часть приложений | T1, T2 для пропущенных им приложений, T3 кроме запросов его сети | Root · общий |
| любой, с включённым **Забирать устройство всегда** | T1 + T2 + T3 | Root |

Приложения другого VPN сохраняют его туннель и DNS, если не забрать устройство.
SOCKS5-прокси работает всегда: направьте на него приложение или исходящее
соединение другого VPN, чтобы попасть в NetBird и на выходной узел через него.

В другом VPN полезно исключить BirdSocks из его туннеля и держать его
собственные адреса вне диапазона NetBird.

## Проверка

```sh
su -c 'ip rule show'                    # 89, 90 и, с выходным узлом, 151/191/201
su -c 'ip route show table 25203'       # диапазон NetBird, резолвер, throw защиты
su -c 'ip route show table 25204'       # выбранные сети, маршрут по умолчанию
su -c 'ip route get 8.8.8.8'            # → birdsocks0 с выходным узлом
su -c 'ip route get 192.168.1.1'        # локальная сеть → wlan0
su -c 'iptables -t nat -S BIRDSOCKS_DNS'
```

После остановки BirdSocks ни этих приоритетов, ни таблиц, ни цепочек остаться
не должно. Строки помощника — в **Диагностика → Журналы** (категория CORE,
«Root VPN»).

Приоритеты 89/90/151/191/201 и таблицы 25203/25204 (25213/25214 у отладочной
сборки) принадлежат только BirdSocks.
